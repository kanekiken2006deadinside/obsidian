# Диаграмма Ганта: редизайн интернет-магазина «Триал-Спорт»

**Легенда проекта.** Сеть «Триал-Спорт» заказала полный редизайн сайта trial-sport.ru: от исследования пользователей до запуска нового сайта. В основе проекта — твои работы: аудит, персоны, CJM, функциональная карта, user flow, прототип «Начни со своего спорта».

**Сроки:** старт 01.12.2026, запуск 26.03.2027 (75 рабочих дней, около 4 месяцев), затем 2 недели мониторинга до 08.04.2027.
**Трудозатраты:** 1314 часов.
Выходные и праздники (31.12, 1–8 января, 23 февраля, 8 марта) в расчёт не входят.

## Три схемы зависимостей (пункт 3 ТЗ)

| Схема | Тип связи в GanttPRO | Пример в проекте |
|---|---|---|
| **Последовательная** | Finish-to-Start (окончание → начало): следующая задача начинается, когда закончилась предыдущая | 2.1 Функциональная карта → 2.2 User flow → 2.3 Прототип главной |
| **Параллельная** | Start-to-Start (начало → начало): задачи идут одновременно | 1.2 UX-аудит и 1.3 Анализ конкурентов; 2.3 и 2.4 прототипы; 5.1 и 5.2 тестирование |
| **Зависимая** | Задача ждёт окончания **нескольких** задач, часто из разных этапов | 4.5 Вёрстка главной ждёт и 3.2 Дизайн главной, и 4.4 Вёрстку компонентов; 5.1 Тестирование ждёт 4.3, 4.7, 4.8 и 4.9 |

Ещё одна видимая на диаграмме особенность: разработка (этап 4) начинается **параллельно** с дизайном (этап 3), сразу после утверждения прототипов. Бэкенд и контент не ждут готового дизайна, это экономит около месяца.

## Как сделать в GanttPRO — куда нажимать

Кнопки ниже взяты из справки GanttPRO (английский интерфейс). Если у тебя русский интерфейс, кнопки называются по смыслу так же — в скобках дан вероятный перевод.

### Шаг 1. Регистрация
1. Открой ganttpro.com → **Sign up** (Зарегистрироваться). Проще всего войти через Google.
2. На вопросы анкеты (роль, размер команды) отвечай как угодно — на работу это не влияет.

### Шаг 2. Новый проект
1. В левом верхнем углу нажми **Create a new project** (Создать новый проект).
2. Выбери **Create a new project**, а не «portfolio».
3. В окне **Add new project** впиши название «Редизайн trial-sport.ru» и дату начала 01.12.2026. Шаблон не выбирай — нужен пустой проект.

### Шаг 3. Настройки проекта (до ввода задач)
1. В правом верхнем углу нажми **Project settings** (Настройки проекта, значок шестерёнки).
2. **Duration step** (Шаг длительности) — поставь **days** (дни), чтобы длительность вводилась в днях.
3. **Change the current working week** (Рабочая неделя / календарь) — оставь Пн–Пт рабочими и добавь нерабочими днями 31.12.2026, 01–08.01.2027, 23.02.2027 и 08.03.2027.
4. **Auto scheduling** (Автопланирование) — оставь включённым: тогда при связях даты задач пересчитываются сами.

### Шаг 4. Включить нужные колонки
1. Над списком задач справа нажми значок **+** (или «Custom fields» → вкладка **Standard fields**).
2. Поставь галочки: **Work breakdown structure** (номера 1, 1.1…), **Assigned** (Исполнитель), **Duration** (Длительность), **Estimation** (Трудозатраты / оценка), **Status** (Статус), **Priority** (Приоритет), **Start date** и **End date**.

### Шаг 5. Этапы и задачи
1. Внизу списка нажми **Add a task** (Добавить задачу) и впиши «Концепция и анализ». Так же создай остальные 4 этапа.
2. Чтобы добавить задачу внутрь этапа: наведи на строку этапа → **три точки** справа → **Add a task**. Как только у этапа появилась подзадача, он становится группой, и его длительность считается по подзадачам автоматически.
3. Порядок задач можно менять перетаскиванием строк.
4. Введи все задачи из таблицы «План работ» по номерам.

### Шаг 6. Длительность, трудозатраты, исполнитель
Для каждой задачи:
1. В колонке **Duration** впиши число дней из таблицы (например, `5`).
2. В колонке **Estimation** впиши часы с буквой `h` (например, `40h`).
3. Нажми ячейку **Assigned** → **Add assignee** → отметь исполнителя → **Ok**. Если исполнителей ещё нет, нажми **+Add more people** и добавь роли («UX-дизайнер», «Frontend-разработчик» и т. д.) как ресурсы без приглашения людей.
4. Заполни **Priority** и **Status** (у задач 1.2–1.5 и 2.1–2.3 — «Done» / «Выполнено»).

Удобнее всё то же сделать в окне задачи: двойной клик по полоске задачи → **Task settings** → **Set duration**, **Set estimation**, **Add assignee**.

### Шаг 7. Вехи
1. Для 1.6, 2.7, 3.6, 5.5: наведи на строку → **три точки** → **Convert to milestone** (Превратить в веху). Или создай сразу кнопкой **Add a milestone** внизу списка.
2. На диаграмме веха станет ромбиком.

### Шаг 8. Зависимости (стрелки)
**Способ 1 — мышкой:** наведи на полоску задачи, справа и слева появятся маленькие кружки.
- **Последовательная (Finish to Start):** тяни кружок с **конца** задачи к **началу** следующей. Пример: 2.1 → 2.2.
- **Параллельная (Start to Start):** тяни кружок с **начала** задачи к **началу** другой. Пример: 1.2 → 1.3.
- **Зависимая:** проведи к одной задаче несколько стрелок. Пример: к 5.1 — от 4.3, 4.7, 4.8 и 4.9.

**Способ 2 — через окно задачи** (надёжнее): двойной клик по полоске → **Task settings** → **Add dependency** → выбери задачу-предшественника → тип **Finish to Start** или **Start to Start** → **Save**.

Ошиблась со стрелкой — кликни по ней → **Delete dependency** и нарисуй заново. Отдельной кнопки смены типа в справке нет, поэтому проще удалить и создать новую.

После связей проверь даты: при включённом автопланировании они должны совпасть с таблицей. Если какая-то дата не совпала — проверь праздники в шаге 3.

### Шаг 9. Оформление
1. Клик по полоске → цвет: каждому этапу свой цвет.
2. Справа вверху выбери масштаб **Weeks** или **Months** (Недели / Месяцы), чтобы вся диаграмма помещалась на экран.

### Шаг 10. Ссылка для просмотра
1. В правом верхнем углу нажми значок **Share** (Поделиться).
2. Нажми **Create link** (Создать ссылку). Галочку **Snapshot** не ставь — тогда по ссылке всегда видна актуальная версия. Пароль не включай.
3. Нажми значок копирования и вставь ссылку в отчёт. Регистрация для просмотра не нужна.

### Шаг 11. Скриншот
1. В правом верхнем углу нажми значок **Export** (Экспорт).
2. Выбери формат **PNG** (или **PDF**), ориентацию **landscape** (альбомная) и масштаб так, чтобы вся диаграмма влезла.
3. Если экспорт недоступен на твоём тарифе — сделай обычный скриншот экрана (Win + Shift + S).

## Сценарий видео-ревью (до 3 минут)

1. **Задача (15 с).** «Это план полного редизайна сайта „Триал-Спорт“ — от исследования пользователей до запуска».
2. **Этапы (40 с).** Пройди по пяти этапам сверху вниз, назови даты каждого.
3. **Зависимости (40 с).** Покажи по одной стрелке каждого типа: последовательную (2.1 → 2.2), параллельную (1.2 и 1.3), зависимую (5.1 ждёт четыре задачи). Отдельно скажи, что разработка идёт параллельно с дизайном и экономит около месяца.
4. **Вехи (15 с).** Четыре точки, где заказчик утверждает результат.
5. **Сроки и трудозатраты (40 с).** Старт 1 декабря, запуск 26 марта — 75 рабочих дней, 1314 часов. Больше всего часов у UX-дизайна и разработки. Самые долгие задачи — наличие в магазинах в реальном времени (80 ч) и контент для «Скалолазания» (80 ч).
6. **Риски (20 с).** Новогодние праздники растягивают проектирование; интеграция с остатками магазинов может занять больше времени; на это заложить 15–20 % запаса.
